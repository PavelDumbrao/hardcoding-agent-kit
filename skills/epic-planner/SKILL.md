# Epic Planner Skill

## Принцип "30 минут"
Любая крупная задача разбивается на подзадачи по 15-30 минут. Это обеспечивает постоянный прогресс, снижает риск ошибок и позволяет делать коммиты после каждого чанка.

## Разница между Reasoning и Decomposition
- **Reasoning** (рассуждение): "Как решить эту конкретную задачу?" — пошаговое обдумывание одной проблемы.
- **Decomposition** (декомпозиция): "Какие задачи нужно решить?" — выявление множества подзадач и их организация в план.

## Алгоритм декомпозиции

### 1. Анализ требований
Пойми конечную цель эпика. Задай вопросы:
- Что именно должно работать в конце?
- Кто будет этим пользоваться?
- Какие ограничения (время, технологии, бюджет)?

### 2. Определение слоев
Раздели задачу по архитектурным слоям:
- **Database**: Миграции, схемы, seed-данные.
- **Backend/API**: Эндпоинты, бизнес-логика, валидация.
- **Frontend/UI**: Компоненты, формы, навигация.
- **Tests**: Unit, integration, E2E.
- **DevOps**: Деплой, CI/CD, переменные окружения.

### 3. Создание шагов
Каждый шаг должен быть:
- **Конкретным**: Указывай файлы, компоненты, функции.
- **Проверяемым**: Чёткий критерий завершения (Definition of Done).
- **Самодостаточным**: Можно сделать коммит после выполнения.
- **Атомарным**: 15-30 минут, не больше.

### 4. Оценка зависимостей
Расставь шаги в правильном порядке. Используй маркеры:
- `[blocked by: #3]` — зависит от шага 3.
- `[parallel]` — можно делать параллельно с другими.

### 5. Фиксация плана
Запиши в `progress.md` (Memory Bank) или используй `task_progress`.

## Стратегии декомпозиции

### Плоский список (простые задачи)
```
- [ ] Шаг 1
- [ ] Шаг 2
- [ ] Шаг 3
```

### Иерархическая декомпозиция (сложные задачи)
```
- [ ] Эпик: Авторизация
  - [ ] Подзадача: Настройка OAuth
    - [ ] Создать проект в Google Cloud (15 мин)
    - [ ] Настроить провайдера (20 мин)
  - [ ] Подзадача: UI
    - [ ] Кнопка входа (15 мин)
    - [ ] Страница профиля (25 мин)
```

### Последовательный vs Параллельный
- **Sequential**: Шаги зависят друг от друга (БД → API → UI).
- **Parallel**: Независимые задачи (тесты + документация).

## Пример полной декомпозиции

**Эпик**: "Добавить авторизацию через Google"

❌ Неправильно:
- [ ] Сделать авторизацию

✅ Правильно:
- [ ] Создать проект в Google Cloud Console и получить Client ID (15 мин)
- [ ] Добавить env-переменные GOOGLE_CLIENT_ID/SECRET (5 мин)
- [ ] Установить и настроить NextAuth.js (20 мин)
- [ ] Создать API route `/api/auth/[...nextauth]` (15 мин)
- [ ] Добавить кнопку "Войти через Google" на `/login` (15 мин)
- [ ] Реализовать middleware для защищённых страниц (20 мин)
- [ ] Проверить сохранение пользователя в БД после входа (20 мин)
- [ ] Написать тест для редиректа неавторизованного пользователя (15 мин)

## Правила формулировки
- Используй глаголы действия: "Создать", "Настроить", "Добавить", "Проверить", "Написать".
- Указывай конкретные файлы/компоненты: `src/pages/login.tsx`, а не "страница логина".
- Добавляй оценку времени в скобках: `(15 мин)`.
- Каждый шаг — один коммит.

## Антипаттерны
- ❌ Слишком крупные шаги (> 30 мин) — разбей дальше.
- ❌ Размытые формулировки ("доделать фичу") — конкретизируй.
- ❌ Пропуск зависимостей — убедись, что порядок правильный.
- ❌ Отсутствие критериев завершения — добавь DoD.
