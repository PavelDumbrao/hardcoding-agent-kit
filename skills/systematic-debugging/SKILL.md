# Systematic Debugging Skill

Отладка — это не магия, а детективная работа. Системный подход экономит часы блуждания по коду.

## Главный принцип
**Устраняй причину, а не симптом.** Root Cause Analysis — найди истинную причину сбоя, не маскируй ошибку.

## Алгоритм отладки (7 шагов)

### 1. Воспроизведение
Создай минимальный воспроизводимый пример (MRE). Если баг не воспроизводится стабильно — собери больше данных (логи, условия, окружение).

### 2. Изоляция (Binary Search Debugging)
Раздели код пополам и систематически исключай секции, пока не найдёшь проблемный участок:
```python
def debug_process():
    step_a()
    # Заменяем потенциально проблемный компонент упрощённой версией
    # step_b()
    debug_step_b()  # Упрощённая версия
    step_c()
```
**Git Bisect** — автоматизированный бинарный поиск по истории коммитов:
```bash
git bisect start
git bisect bad          # Текущий коммит — сломан
git bisect good abc123  # Этот коммит — рабочий
# Git автоматически переключается между коммитами
# Тестируй и отмечай: git bisect good / git bisect bad
git bisect reset        # Завершение
```

### 3. Анализ логов
Изучи stack trace, логи сервера/браузера. Ищи первую ошибку в цепочке — она обычно корневая.

### 4. Формирование гипотез
Составь список причин от наиболее вероятных к наименее. Типичные категории:
- **Данные**: null/undefined, неправильный тип, пустой массив
- **Состояние**: race condition, stale state, кэш
- **Окружение**: env-переменные, версии зависимостей, OS
- **Сеть**: timeout, CORS, неправильный URL
- **Логика**: off-by-one, неправильное условие, пропущенный edge case

### 5. Проверка
Проверяй **одну гипотезу за раз**, внося минимальные изменения. Если менять несколько вещей сразу — не узнаешь, что помогло.

### 6. Исправление
Устрани причину. Убедись, что фикс не ломает другие части (регрессия).

### 7. Предотвращение
Напиши тест, который поймает этот баг, если он вернётся:
```javascript
test('user.bio defaults to empty string when undefined', () => {
  const user = createUser({ name: 'Test' });
  expect(user.bio).toBe('');
});
```

## Инструменты

### Semantic Code Search (до чтения файлов)
Если проект > 20 файлов или кодовая база незнакома — SHOULD сначала использовать `github.com/cocoindex-io/cocoindex-code` → `search` до чтения файлов вручную.

Паттерн:
1. semantic search: «где обрабатывается X», «как устроен retry», «где валидируются данные»
2. read_file по 1–3 лучшим результатам
3. изоляция проблемного участка
4. гипотеза и проверка

Примеры запросов для отладки:
- «where is error handling for HTTP requests»
- «where is the auth middleware»
- «where are environment variables loaded»
- «how is the retry logic implemented»

### Browser DevTools
- **Network tab**: Статусы запросов, тайминги, payload
- **Console**: Ошибки, warnings, `console.log`
- **Sources**: Breakpoints, step-through, watch expressions
- **Performance**: Profiling, flame charts

### Командная строка
- `curl -v URL` — детальная информация о HTTP-запросе
- `docker logs container --tail 50` — логи контейнера
- `git log --oneline -20` — последние коммиты
- `git diff HEAD~1` — что изменилось в последнем коммите

### Тестирование
- **Jest / Vitest**: Unit-тесты
- **Playwright**: E2E-тесты
- **Sentry**: Мониторинг ошибок в продакшене

## Правила логирования
```javascript
// ✅ ПРАВИЛЬНО: контекст + данные
console.log('[DEBUG: UserService] saveUser input:', JSON.stringify(user, null, 2));
console.log('[DEBUG: UserService] saveUser result:', result.id);

// ❌ НЕПРАВИЛЬНО: бесполезно
console.log('here');
console.log(data);
```

### Уровни логирования
- `console.error()` — ошибки, требующие внимания
- `console.warn()` — потенциальные проблемы
- `console.log()` — информация для отладки (удаляй после!)
- `console.debug()` — детальная отладочная информация

## Техники для сложных багов

### Delta Debugging
Систематически уменьшай входные данные, вызывающие ошибку, пока не найдёшь минимальный набор, воспроизводящий баг.

### Rubber Duck Debugging
Объясни проблему вслух (или напиши). Часто само объяснение помогает найти ошибку.

### Time Travel Debugging
В некоторых средах (Redux DevTools, rr debugger) можно перемотать выполнение назад и посмотреть состояние в любой момент.

## Пример полного процесса
```
Баг: "500 при сохранении профиля"

1. Воспроизведение: POST /api/profile с полем bio = undefined → 500
2. Изоляция: Network tab — запрос уходит корректно, ошибка на сервере
3. Логи сервера: TypeError: Cannot read property 'length' of undefined (userService.ts:45)
4. Гипотеза: поле bio приходит как undefined, но код вызывает .length
5. Проверка: console.log(req.body.bio) → undefined. Подтверждено.
6. Исправление: const bio = req.body.bio ?? ''
7. Тест: добавлен тест для undefined bio
```

## Антипаттерны отладки
- ❌ Менять код наугад ("а что если попробовать так?")
- ❌ Менять несколько вещей одновременно
- ❌ Игнорировать stack trace
- ❌ Оставлять `console.log` в продакшене
- ❌ Не писать тест после исправления
