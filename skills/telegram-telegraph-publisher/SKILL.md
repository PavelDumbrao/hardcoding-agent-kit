# Telegram + Telegraph Publisher

Коротко: skill превращает одну тему или черновик в связанную пару материалов: короткую подводку для Telegram и полный лонгрид в Telegraph. При явном запросе он публикует статью, вшивает ссылку в CTA, отправляет сообщение через Telegram user-session и проверяет живую карточку предпросмотра.

## Когда использовать

- «Сделай краткий пост и полный лонгрид в Telegraph».
- «Оформи как на скриншоте: коротко, ссылка вшита, ниже карточка».
- «Опубликуй статью и скинь сразу в Избранное».
- Нужно упаковать практический кейс Павла: личный результат, факт-чек, выводы и подробный разбор.

## Когда НЕ использовать

- Нужен только обычный Telegram-пост без лонгрида.
- Нужен Bot API, рассылка или inline-клавиатура: используй `telegram`.
- Нужна только работа с Telegram от user-session без редакторской упаковки: используй `telegram-user-session`.
- Пользователь просит только черновик: не публикуй в Telegraph и не отправляй сообщение.

## Маршрутизация навыков

Этот skill является входным оркестратором:

1. Свежие факты: официальные источники и web-поиск.
2. Публикация Telegraph: `browser-automation` или доступный браузерный инструмент текущего агента.
3. Отправка от аккаунта Павла и проверка `Избранного`: `telegram-user-session`.
4. Bot API нужен только если пользователь явно просит сообщение от бота или настоящую inline-кнопку.

Подробная карта переходов: `docs/skill-graph.md`.

## Контракт результата

По умолчанию подготовь два связанных текста.

### Telegram teaser

Структура:

1. `🤖` + сильный личный hook в первой строке.
2. Один плотный абзац: что произошло и что читатель получит.
3. Отдельная строка со вшитой ссылкой: `📖 Полный разбор`.
4. Включённый предпросмотр Telegraph.

Правила:

- Не показывай голый URL, если клиент поддерживает ссылку в тексте.
- Используй одну главную ссылку, чтобы Telegram выбрал правильную карточку.
- Для HTML-отправки: `<a href="{URL}">📖 Полный разбор</a>` и `disable_preview=false`.
- Не дублируй содержание лонгрида в подводке.
- Не используй длинное тире. Предпочитай двоеточия, точки и короткие фразы.
- Не добавляй хештеги, рекламные обещания и лишние CTA без запроса.

Базовый шаблон: `templates/telegram-teaser.md`.

### Telegraph longread

Структура:

1. Заголовок с личным результатом, конфликтом или неожиданным наблюдением.
2. Первый жирный абзац: краткое содержание. Он влияет на текст карточки в Telegram.
3. Короткий личный вход без долгого разгона.
4. Основные разделы: что произошло, доказательства, ограничения, практический метод, вывод.
5. Честные оговорки: личный опыт отдельно, официальные факты отдельно.
6. Источники в конце, если есть свежие или проверяемые утверждения.

Для Павла по умолчанию:

- язык: русский;
- автор: `Pavel Dumbrao`;
- тон: практик и предприниматель, без канцелярита и AI-пафоса;
- важнее реальный результат, чем общие рассуждения;
- названия моделей, CLI, API и продуктов оставлять на английском.

Базовый шаблон: `templates/telegraph-longread.md`.

## Workflow

### 1. Зафиксировать источник и границы

- Прочитай вложение, черновик, скриншот или указанный материал.
- Выдели личные факты, проверяемые внешние факты и мнения автора.
- Если тема зависит от текущих моделей, лимитов, цен, интерфейсов или правил, проверь официальные источники.
- Не выдумывай детали ради красивой истории.

### 2. Найти центральный сюжет

Сформулируй одну главную мысль, которую можно выразить одной строкой.

Хороший сюжет:

> 27 часов. Одна цель. На выходе: работающий сервис. И куда я пропал.

Слабый сюжет:

> Большой обзор последних обновлений AI.

### 3. Написать лонгрид первым

- Сначала собери полную аргументацию и источники.
- Убери повторы между введением, разделами и выводом.
- Оставь 5-9 основных разделов, если тема не требует большего.
- Сделай первый жирный абзац самостоятельным описанием статьи для preview-карточки.

### 4. Сжать лонгрид в Telegram teaser

- Не пересказывай всю статью.
- Оставь hook, главный вывод и обещание пользы.
- Вшей ссылку в `📖 Полный разбор`.
- Подводка должна хорошо читаться даже до загрузки карточки.

### 5. Опубликовать, только если это явно запрошено

- Открой Telegraph через браузер.
- Перед действиями получи accessibility snapshot или DOM-состояние.
- Заполни title, author и тело статьи с сохранением заголовков, списков, цитат и ссылок.
- Нажми Publish только при явном разрешении на публикацию.
- Проверь опубликованный URL, заголовок, первый абзац, структуру и отсутствие ошибок в консоли.
- Закрой браузер после проверки.

### 6. Отправить, только если указан адресат

- Для `Избранного` используй `telegram-user-session` и entity `me` либо подтверждённый self `user_id`.
- Для другого чата нужен точный recipient или `chat_id`.
- Отправляй HTML с `disable_preview=false`.
- Не отправляй дубли после неоднозначного ответа. Сначала ищи по `request_id`, `message_id` или уникальной фразе.

### 7. Подтвердить пользовательский результат

Минимум:

- Telegraph URL открывается;
- статья имеет правильный title;
- отправка вернула `message_id`;
- целевой `message_id` найден в нужном чате;
- сообщение содержит правильную ссылку.

Для полного visual contract проверь, что Telegram создал `MessageMediaWebPage` и её `webpage_title` совпадает с заголовком статьи. Если HTTP API не показывает preview metadata, допустима одна короткая read-only Telethon-проверка с немедленным disconnect и последующей проверкой health движка.

## Ограничение Telegram

Обычное сообщение от user-session не может содержать настоящую bot inline-клавиатуру. В `Избранном` визуальный CTA обеспечивает сама карточка Telegraph с кнопкой `Просмотреть`. Если пользователь просит отдельную inline-кнопку под сообщением, нужен бот и явный Bot API сценарий.

## Smoke tests

- «Сделай кратко + Telegraph, но не публикуй» -> два черновика, никаких внешних действий.
- «Опубликуй и скинь в Избранное как на скриншоте» -> статья, вшитая ссылка, preview-карточка, `message_id`, проверка доставки.
- «Отправь в мой канал» без названия -> подготовить тексты, но запросить точный канал до отправки.
- «GPT теперь никогда не ошибается» -> переписать опасный абсолют и отделить личное наблюдение от официального факта.

## Red flags

- Голый Telegraph URL виден отдельной строкой, хотя можно вшить ссылку.
- Первый абзац статьи пустой, общий или плохо выглядит в карточке.
- Подводка повторяет половину лонгрида.
- Личный опыт подан как универсальное правило.
- Публикация или отправка выполнена без явного запроса.
- Агент сообщил об успешной доставке только по HTTP 200, не проверив `message_id`.
- После неоднозначной отправки выполнен повтор без аудита, из-за чего появляется дубль.
- Заявлена inline-кнопка от user-session, хотя существует только Telegraph preview CTA.

## Финальная выдача

Сообщи кратко:

- URL статьи;
- куда отправлено;
- `message_id`;
- создана ли preview-карточка;
- что осталось только черновиком или не проверялось.
